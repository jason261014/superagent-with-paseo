# Superagent with Paseo 本地优先设计

> 日期：2026-11-05
> 状态：讨论稿，等待审阅；本文描述目标，不表示功能已经交付。
> 基础：DeepSeek `dsh-superagent-prototype` fork，当前开发基线 `cbc141c`。

## 1. 目标和使用边界

我们在同一个 DeepSeek fork 中构建个人本地工具。用户通过 Paseo 主 agent 对话或本地 CLI 发出自然语言工作；主 agent 负责理解、拆分、调度、处理问题、评审和决定接受具体交付。执行者可以并行工作。用户不必维护 contract、binding 或手工搬运消息。

首个可用版本以本机为执行地点，支持代码和非代码任务，完成派发、问题反馈、成果固定、评审返工和明确收尾。已有 SSH/Paseo 和跨机经验保留为后续接入依据，不宣称本机通过就等于远端通过。

默认不监听 GitHub、飞书等外部来源，也不主动接单。需要在协调者回合结束后继续工作的内部反馈服务属于任务运行的一部分，不等于启用外部来源监听。原型的 GitHub/飞书和 DSH 运行路径保留；本地宿主不要求配置 GitHub 或飞书。

## 2. DSH、Paseo 与多 runtime 的关系

这项改造包含运行时适配，但不是单纯把一个 `DSH Runtime` 类替换为另一个 runtime adapter：

| 层 | 选择 | 责任和边界 |
| --- | --- | --- |
| 模型执行和会话 | 本地路径接入 Paseo | 管理协调者和执行者会话、支持的 provider/model、发送、观察和中断；Paseo 的每种 provider 能力仍以实际验证为准。 |
| 任务协调 | 继续复用并调整 DeepSeek Engine 及持久化机制 | 记录任务和执行实例、待处理反馈、授权边界、交付版本和处置，不由模型会话本身充当唯一事实源。 |
| 产品宿主 | 在本 fork 内增加本地宿主 | 组装 Engine、SQLite、effect 队列、Paseo 适配、入口及服务生命周期，解除本地路径对 DSH/Cordis 和 GitHub setup 的运行时要求。 |
| 现有 DSH 路径 | 保留 | 原型的 DSH Runtime 和已有 Source 继续使用其原有行为，不强行迁移现有任务。 |

Paseo 是本地路径首个会话后端；它可使用的不同 provider/model 是 Paseo 的能力。保留 Executor、协调者和 Source 的清晰边界，但首版不实现通用多后端插件平台，也不承诺所有模型、运行时都有相同中断、工具和消息语义。原型已有 DSH 路径仍存在，不代表新本地宿主已经支持 DSH 后端。

## 3. 使用方式与协调者

推荐以 Paseo 管理的本地主 agent 作为长期协调者。用户可直接在其对话中下达任务；CLI 是提交、查询和管理同一任务的本地入口。例如下列命令仅展示目标接口，实际参数以实现计划为准：

```text
superagent run "检查服务健康接口并实现缺失的部分"
superagent status
superagent result <task>
superagent send <task> "请补充异常路径的测试"
superagent stop <task>
```

`run` 的请求进入同一个协调者工作流，由主 agent 判断是否拆分和如何派发；CLI 成功接收不代表任务已派发或完成。CLI 和主 agent 读取同一事实源，任务绑定唯一协调者。当前 Codex 桌面会话可以在活跃回合调用 CLI 和读取结果，但没有已验证的公开能力保证其回合结束后被本工具唤醒；长期后台协调由 Paseo 主会话承担，不能把当前聊天上下文假定为已同步。必要资料须明确交接。

查询、诊断命令只读，不创建任务、启动服务或派发。服务安装、启动和停止是明确操作，不通过查询暗中发生。外部消息或文件是任务数据，不能自行扩大目标和授权；涉及审批或流程中心申请时遵守用户已明确设定的授权约束。

## 4. 组成与事实源

```text
Paseo 对话 / 本地 CLI
          │
          ▼
  本地入口与协调者适配 ─── Paseo 主会话
          │                     ▲
          ▼                     │ 持久化待处理事项与通知
本地宿主：Engine + SQLite + Effects + 交付存储
          │
          ▼
 Paseo 执行适配 ─── 执行者会话 + 独立工作目录
```

- **本地入口**：接收用户或已授权调用方的明确操作，传输方式及访问控制由实施计划落实；用户请求和 agent 工具调用的来源需可区分。不得凭请求正文伪造调用者、把 localhost 或同源校验视为充分鉴权。重复操作须用稳定身份和内容摘要；相同身份不同内容拒绝。
- **任务核心**：复用 DeepSeek 的任务、执行实例和事务/效果模型，按本地使用调整领域语义。运行观测、执行者报告、检查证据和接受结论分开保存。
- **本地持久化服务**：一个私有状态目录使用单一协调者所有者锁和一个权威 SQLite Store；效果在事务提交后执行，进程重启后恢复。原始事件、队列和交付是事实；视图可以重建。不得同时让 DSH 宿主和本地宿主双写一个状态目录。
- **协调者适配**：向主会话发送稳定身份的通知，主 agent 使用受支持的工具/CLI 读取原文、派发工作、答复、组织评审和记录结论。消息已发送、主会话已收到和已处置不是同一事实；主 agent 正忙时排队，不默认中断。
- **执行适配**：为执行实例冻结配置，建立/找回 Paseo 会话，发送输入并观察；通过与执行实例绑定的报告桥接收反馈。不得从普通聊天文本或空闲状态推断正式交付。
- **交付与检查**：取回固定的原始成果、摘要和版本；检查与评审结果绑定明确版本，由主 agent 或用户作最终处置。

本地 Source 已有的 UID 映射和 `sameOrigin` 检查都不是完整调用者认证。执行前必须验证入口的真实身份和权限边界，不能将实验接口直接暴露为无鉴权 API。

## 5. 任务与交付生命周期

1. 用户明确提交工作；主 agent 识别需要的目标、自然语言说明、代码基线或原始文件，并在已有授权内选定执行环境。
2. 工具冻结目标、provider/model、权限模式、输入与来源映射；缺失权限模式拒绝执行，不默认扩大权限。代码任务建立独立工作目录，非 Git 任务也有独立工作目录；worktree 不构成安全沙箱。
3. 写入稳定任务与操作身份，再创建或对账 Paseo 执行实例。任务与执行实例分离，重试或换执行者不得让旧实例的迟到事件修改当前实例。
4. 执行者报告进度、需要输入、交付或执行异常。普通进度更新视图；问题、可评审交付及需要处理的异常进入主 agent 队列。报告桥必须持久化接收并与执行实例绑定，覆盖启动回写前的早到报告。
5. 交付固定为不可被后续工作修改的 `deliveryId`。代码交付至少固定基线与完整变更，包括新增、删除、二进制、未跟踪文件及可执行位；非代码交付固定所选原始文件。缺失或不完整的成果不得标为可评审。传输完整性和存储范围要校验，不能读取任意远端路径。
6. 主 agent 读取完整成果和证据，必要时运行可复验检查或安排独立评审。检查的执行环境和条件须记录；在执行者工作目录中运行检查不等于独立隔离环境。检查通过或执行者声明完成都不自动接受。
7. 主 agent 明确记录针对某个 `deliveryId` 的接受或返工；返工原则上沿用执行会话和工作目录，产生新的交付版本。只有明确收尾后逻辑归档，默认不删除成果或工作目录。

原型无 PR 的 `ready` 可能直接结束 Ticket；本地路径必须改变这一语义，保证完整交付和显式接受分开。DSH 路径及其已有任务维持旧语义，不能让本地新行为改变原型现有结果的解释。

## 6. 消息、恢复与停止

- 写入意图后再做外部副作用。创建或发送结果不明时，先按稳定会话标签、执行身份和消息 ID 对账；缺失分页、多个匹配或无法确认均保持未知，不盲目重复创建或发送。
- 接收、通知、实际读取和处置分别记录。事件先持久保存再确认接收；主 agent 不在线时保留待处理事项。仅时间线出现消息不自动证明模型读过或处置完毕。消息与早到报告须能在崩溃后恢复；旧实例的迟到报告不得改变当前实例。
- `stop` 通过 Paseo 的实际中断能力，使用已核实的单一完整会话 ID。请求已送达、回合观察到空闲、稳定停止和子进程退出是不同事实。已知探针不能证明全部子进程退出；当前尚无经过验证的消息队列栅栏，发出的消息可能在观察空闲后再次唤醒会话。不能把一次空闲观察记为稳定停止；能力不足时保留待确认并报告原因。
- 断线不等于执行失败；进程恢复不能自动换执行者、自动扩大权限、自动合并或删除工作目录。多次重连失败应避免重复打扰。
- 文件快照当前实验实现不是跨文件原子快照，存在活跃或不可信目录中的父目录替换竞争，也不承诺崩溃持久性。实现必须先解决或明确约束采集时机、可信范围、完整性和持久化，再作为正式交付依据；不把现有函数当作已完成的安全边界。

## 7. 首版范围与明确不做

首版：本地 CLI 和 Paseo 主会话、本机 Paseo 执行、私有持久化反馈、受控材料和工作目录、代码及非代码固定交付、版本化评审返工、诊断与停止状态呈现。可复验检查是可选证据而非通用任务必填的 contract。

首版不启用 GitHub/飞书监听、主动任务、自动合并/push/部署、流程中心申请、自动删除成果、通用 DAG 调度、多设备高可用、独立 MCP 服务和通用插件市场。保留现有 DSH 路径不表示首版本地宿主要运行两套模型协调器。SSH 远端目标在本机闭环稳定后设计和验证，不作为本机端到端通过的推论。

## 8. 验收

自动化覆盖：操作身份冲突、创建/发送不明、重复消息和事件、迟到报告、报告早到、接收与处置分离、重启恢复、单所有者锁、权限边界、目标/基线固定、两个工作目录互不串用、版本化交付和返工、检查与接受分离、停止未知状态，以及官方 DSH 原路径回归。

真实演示必须在明确选定的演示环境中进行，而非凭 mock 结论替代：

1. 从 CLI 或 Paseo 对话发起一个小代码任务和一个非代码任务；取回两类原始成果。
2. 执行者报告一个确需处理的问题，主 agent 在当前回合结束后收到、读取并明确处置；普通进度不单独唤醒。
3. 对第一版提出修改，原执行者提交第二版；第一版仍可读取，接受结论准确指向第二版。
4. 在执行与消息关键时刻重启本地服务，证明不会无依据地重复派工，并能保留和补收未处置反馈。
5. 请求中断一项运行中的演示任务，分别记录请求、观察和尚无法证明的停止/子进程状态；不得以 idle 冒充稳定停止。
6. 无 GitHub/飞书凭据或监听配置时，本地路径仍能使用；官方 DSH 路径回归不受影响。

验收报告分别说明自动化、真实运行环境和未验证项。仓库现有 1238 项测试及实验探针不能代替本设计闭环验收。
